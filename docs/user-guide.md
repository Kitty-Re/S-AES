# 用户指南

## 1. 启动

双击项目根目录的 `启动程序.bat`，或在 PowerShell 中进入项目目录：

```powershell
Set-Location S-AES
.\.venv\Scripts\python.exe -m saes_app
```

新环境安装步骤见 [README](../README.md)。本机使用独立 CPython 3.13.7 环境，避免系统默认 Anaconda Python 造成 Qt DLL 冲突；不需要激活虚拟环境。

左侧导航切换六个功能页，亦可用上下方向键。最小窗口为 960 × 640；页面和表格分别滚动。输入二进制必须保留前导零，只接受规定宽度的 `0`、`1`。首尾空白可以去除，内部空白不接受。错误显示在页面标题下方；修改输入会清除相关旧结果。

## 2. 二进制加解密

1. 输入 16 位分组与 16 位密钥。
2. 点击“加密”或“解密”；输入框内按 Enter 执行加密。
3. 使用“复制结果”获得完整 16 位结果。
4. 查看扩展密钥摘要和“计算过程”，滚动表格查看全部 9 个状态。

“填入示例”自动运行 `D728 / 4AF5 → 24EC`。将密文复制到分组框，点击“解密”，应恢复 `D728`。矩阵 `[a c; b d]` 采用列优先顺序，与附录 D 一致。

## 3. ASCII 文本

左侧输入 ASCII 明文，选择 16 位密钥，点击“加密文本”；右侧密文字节可以选择十六进制、二进制或 Base64。切换格式时会转换已有合法密文；格式错误则保留原格式与内容，并提示修正。

默认开启 PKCS#7：奇数字节末尾添加 `01`，偶数字节末尾添加 `02 02`，空明文也添加一个填充分组。关闭填充后只接受偶数字节，空数据合法。

点击“解密密文”，恢复结果显示在下方。加解密双方必须选择相同填充约定。`This is a test` 共 14 个 ASCII 字节，开启填充时得到 16 字节密文：

```text
50 86 C1 5C 1E 3A 22 77 3F 35 50 80 93 64 D3 5D
```

对应 Base64：`UIbBXB46Inc/NVCAk2TTXQ==`。关闭填充时密文只包含前 14 个字节。

密文可能含不可打印字节，因此以无损编码及 Latin-1 转义视图展示。转义视图中的 `\xNN` 是一个原始字节。分组表包含填充字节，最多展示前 200 组；密文编辑框保留完整数据。

中文、表情等非 ASCII 输入会提示具体位置。CBC 页面另提供 UTF-8 长文本。Qt 文本编辑器会规范化换行；逐字节处理控制字符或保留原文件换行时，调用开发接口中的原始 bytes 函数。

## 4. 双重与三重加密

选择模式后输入 16 位分组及对应宽度的组合密钥。“填入示例”按照当前模式填入正确宽度的密钥并执行加密。

| 模式 | 组合密钥长度 | 加密顺序 | 解密顺序 |
|---|---|---|---|
| 双重 EE | 32 bit | E(K1) → E(K2) | D(K2) → D(K1) |
| 三重 EEE，两密钥 | 32 bit | E(K1) → E(K2) → E(K1) | D(K1) → D(K2) → D(K1) |
| 三重 EEE，三密钥 | 48 bit | E(K1) → E(K2) → E(K3) | D(K3) → D(K2) → D(K1) |

密钥从左向右切分，每段 16 位。下方表格显示各级输入、密钥与输出。解密时把密文填回输入框，并保持模式及密钥不变。

## 5. 中间相遇攻击

表格每行包含同一双重密钥下的明文和密文，均为 16 位二进制。双击或按 F2 编辑；“添加一行”新增数据，“删除选中”删除已选行。“填入三组示例”生成已知密钥 `4AF5 + 3A94` 对应的演示数据。

点击“开始完整搜索”，程序先枚举全部 K1 建立中间值表，再枚举全部 K2 反向匹配，并用其他行筛选。进度中的 131,072 表示两侧密钥枚举数量，额外候选验证包含在真实计算耗时中。

单组样例得到 65,470 个候选，不能认定唯一原密钥。本项目的两组、三组样例均只保留 `4AF5 + 3A94`。不同数据的候选数可能不同。

界面显示前 200 对，“导出完整候选 CSV”保存全部结果及完成状态。取消采用协作停止；标为“未完成”的候选只是已检查范围内的结果。任务期间锁定相关输入，其他页面仍可操作。关闭窗口会请求取消并等待线程结束。

## 6. CBC、共享 IV 与篡改对比

1. 输入密钥，点击“随机 IV”生成 16 位初始向量；演示用固定 IV 可以手动输入。
2. 选择 UTF-8 或 ASCII、填充选项并输入长明文，点击“CBC 加密”。
3. 点击“导出 IV 数据包”，JSON 包含密文、IV 和填充约定。接收方“导入数据包”后提供共享密钥、选择原文本编码，再点击“CBC 解密”。
4. 篡改区输入分组序号（从 0 开始），选择“异或翻转”或“整组替换”，输入 16 位掩码或替换值，点击“比较篡改前后”。

数据包不保存密钥或文本编码。随机 IV 来自 `secrets.randbits(16)`。本项目的固定 IV `1234` 仅用于复现实验，普通操作可主动生成新 IV。

对 `C[i]` 翻转掩码 Δ，会改变 `P[i]`，并使 `P[i+1]` 精确异或 Δ；更后的分组不变。最后一组没有后继分组。表格以原始分组比较，保留填充字节；这使末组填充被破坏时仍能查看差异。普通“CBC 解密”仍会检查并移除填充。

点击“填入示例”会完成加密、解密和翻转第一密文组最低位的对比。原始密文不会被比较操作覆盖。

## 7. 算法自检与 CSV

“运行算法自检”核对 7 项教材参数及固定向量。勾选附加选项后，在密钥 4AF5 下遍历全部 65,536 个分组；自检通过不代表执行了全部单元测试。

CSV 表头必须且只能包含 `plaintext,key,ciphertext`，允许调整列顺序。三列均为 16 位二进制文本。可使用 UTF-8 BOM 保留中文软件兼容性。

```csv
plaintext,key,ciphertext
1101011100101000,0100101011110101,0010010011101100
```

“导入并双向验证”逐行检查本组加密是否等于文件密文，并直接解密文件密文以核对原明文；格式错误逐行保存。界面显示前 200 行。其他小组数据尚未进行交换，当前提供的 `local-vectors.csv` 是本地测试数据。见[交叉测试状态记录](cross-test-record.md)。

## 8. 测试与故障定位

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
.\.venv\Scripts\python.exe tools/verify_project.py
```

位数错误先检查前导零和空格；奇数字节原始输入可开启填充；填充错误应核对密钥、IV、密文及约定。若 Qt 无法加载，优先使用项目虚拟环境，检查依赖是否安装完整；不要混用 Anaconda 与 CPython 的 DLL 目录。
