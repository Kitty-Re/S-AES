## 必须对齐的约定

- 分组 16 位，单密钥 16 位；字节按大端排列。`n0 n1 n2 n3` 对应状态 `[[n0,n2],[n1,n3]]`。
- S盒：`9 4 A B D 1 8 5 6 2 0 3 C E F 7`。逆S盒：`A 5 9 B 1 7 8 F 6 0 2 3 C 4 D E`。
- 有限域模 `x^4+x+1`；列混淆 `[[1,4],[4,1]]`，逆列混淆 `[[9,2],[2,9]]`；RCON 为 `80`、`30`。
- 基础单分组不填充。二进制固定保留 16 位；十六进制分组固定 4 位，不带 `0x`。
- 双重 `E_K2(E_K1(P))`；三重为 **48 位 EEE**：`E_K3(E_K2(E_K1(P)))`。组合密钥依次拼接 K1、K2、K3。
- ASCII 每字符一字节，每两字节分组，`plaintext_hex` 是确切字节；`plaintext_text` 中的控制字符按 JSON 转义解析，不能把 `\xNN` 预览当作字面输入。
- 消息 padding 为 `none` 或 `PKCS7_2bytes`。PKCS#7 奇数长度补 `01`，偶数长度（含空串）补 `02 02`。无填充时字节数必须为偶数。
- CBC 仅使用单次 S-AES。`C0=IV`，`Ci=E_K(Pi XOR C_(i-1))`；IV 为 4 位十六进制，解密双方使用相同 IV。
- 篡改分组从 **1** 开始编号，比特 **0 为最低位**。逐块比较使用未去填充的原始字节；填充损坏也应能查看这些字节。

对方若使用另一填充规则或 32 位三重方案，应将对应扩展用例记为 N/A，不能据此判定基础 S-AES 错误。基础 64 组不依赖这些扩展约定。

## 可先手工核对

以下均为十六进制，单分组不填充。加密应得到 C，解密 C 应得到 P。

| P | K | C |
| --- | --- | --- |
| D728 | 4AF5 | 24EC |
| 6F6B | 2D55 | D170 |
| 0000 | 0000 | 071E |
| FFFF | FFFF | 5343 |
| 0001 | 0001 | CE07 |

密钥扩展 `2D55 → (2D55,BCE9,A34A)`；双重 `P=D728,K1=4AF5,K2=1234 → C=4A90`；三重再加 `K3=ABCD → C=0E5D`。

## 中间相遇

完整枚举 K1、K2 各 `0000..FFFF`。仅使用 `D728→73A7` 时应有 **66,009** 个候选，`1234ABCD` 是其中之一；加入 `0000→B50E`、`FFFF→4089` 后应仅剩 **1234ABCD**。不要把单对数据的第一个候选当成唯一答案。

单对测试使用 TXT 的第一行，多对测试使用全部三行。

如需核对全部候选集合：按 `(K1,K2)` 数值升序排序，每对写成 8 位大写十六进制 `K1K2` 加一个 LF，拼接后以 ASCII 编码计算 SHA-256；预期散列见 `05_mitm.json`。无需相同耗时。

## 回填说明

- basic / double / triple48：actual 填固定宽度十六进制结果。
- ASCII / CBC：加密填密文字节十六进制，解密填**去除约定填充后**的明文字节十六进制；空串填空字段并标 PASS。
- tamper：填完整的**未去填充**原始解密十六进制；另在 note 说明填充是否损坏。
- MITM：填候选数及筛选结果；invalid：填 REJECT 或实际行为。未实现的扩展填 N/A。
- 也请在 note 中注明对方小组名、程序版本与测试日期。对方另提供至少一组其自选的 P/K/C，可在本项目反向验证。
- CSV 可用文本编辑器查看；如使用 Excel，请将所有列按文本导入，避免前导零丢失或 16 位二进制数字被改写。

包内所有确定性期望值均已本地核对；基础、消息与篡改使用独立矩阵/多项式参考实现，中间相遇的完整候选集合另由独立枚举核对。本包不包含或声称任何其他小组已通过的记录。
