# 课堂演示说明

本组按照基本加解密、ASCII、多重加密、中间相遇、CBC 和交叉验证的顺序演示实验。本文记录具体操作、观察重点以及对应的截图和数据，便于课堂展示和实验复现。

## 1. 准备

运行 `启动程序.bat`。建议窗口至少 1180×900，便于同时看到结果和过程；较短屏幕可分别滚动页面与表格。操作输入及预期结果详见[通关说明](通关说明.md)。

## 2. 演示顺序

| 时长参考 | 操作 | 应讲述 / 观察的结果 |
|---|---|---|
| 0:00～0:40 | 二进制页填入示例，加密，复制密文后解密 | D728 / 4AF5 → 24EC；轮密钥与逆运算 |
| 0:40～1:15 | ASCII 页填入示例，切换 Base64，再解密 | 两字节分组、填充与无损密文显示 |
| 1:15～1:50 | 双重页示例，再切换两种三重模式 | B2DD、CE12、52E2；EEE 的密钥顺序 |
| 1:50～2:50 | 中间相遇页完整搜索三组，再展示单组和两组 | 候选 65470→1；两侧各 65536 个密钥 |
| 2:50～3:50 | CBC 页填入示例，导出 / 导入数据包，观察篡改表 | IV 共享；第 0、1 组受影响，后续不变 |
| 3:50～4:40 | 自检页运行全部分组检查，导入他组适配 CSV，滚动首尾 | 64/64 双向通过；展示原包与 220 行回填结果 |

表中时间用于安排课堂讲解，算法计算耗时以程序和实验记录为准。

## 3. 中间相遇细节

先保留三行完成一次搜索并导出，说明唯一候选来自全部已知对的交集。再选中第 2、3 行并删除，仅保留 D728→B2DD；重新搜索，展示 65,470 个候选。添加 1234→61AF 后再运行，缩小为 1。若需回到初始状态，点击“填入三组示例”。

本组通过自动测试验证了启动前、建表中和反向匹配中的取消行为。课堂演示中，程序计算结束后显示完整结果；计算期间取消则保留已检查范围内的候选。

## 4. CBC 细节

示例密钥 4AF5、IV 1234、消息 `Hello, S-AES CBC!`。篡改第 0 组、掩码 0001 后，原密文 E334 变为 E335；第 0 组明文从 4865 变为 D860，第 1 组由 6C6C 变为 6C6D，第 2 组及以后不变。解释 `P'[1] XOR P[1]=0001`。

可再演示“整组替换”，或将序号改为最后一组，观察传播范围。比较不覆盖原密文，便于反复切换。

## 5. 证据对应

主要截图是 `01-binary.png`、`02-ascii.png`、`03-double.png`、`04-mitm.png`、`07-triple32.png`、`08-triple48.png` 和 `09-cbc-tamper.png`。实验 CSV 和 JSON 与截图采用相同示例，但耗时属于各自独立运行。所有文件链接见[实验材料索引](evidence/README.md)。

交叉验证导入 `docs/evidence/cross-test/peer-vectors-import.csv`，第一行应为 D728 / 4AF5 → 24EC，最后一行为 CE65 / 6399 → B2B6；解密列分别恢复 D728 和 CE65。配合 `11-peer-cross-top.png`、`12-peer-cross-bottom.png`，说明 64 组基础数据、43 种明文和 43 个密钥均通过。

在终端执行 `tools/verify_cross_test.py`，可展示本组对另一组数据的 220 行计算结果，均为 PASS。对方单组 MITM 数据 D728→73A7 产生 66,009 个候选，三组数据仅剩 1234ABCD，完整候选散列一致。讲解时结合原始输入和本组实际输出，说明两组算法参数及计算结果的一致性。
